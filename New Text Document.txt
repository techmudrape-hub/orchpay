1. Authentication
All API requests require x-api-key and x-api-secret headers. Requests must be sent over HTTPS 
and Content-Type should be application/json.
2. Generate Token
Generate authentication token using merchant credentials (mid, email, secretkey).
curl -X POST "https://yourdomain.com/api/api-payment/generate-token" \
-H "x-api-key: your-api-key" \
-H "x-api-secret: your-api-secret" \
-H "Content-Type: application/json" \
-d '{
"mid": "MERCHANT123",
"email": "merchant@example.com",
"secretkey": "your-merchant-secret"
}'
3. Create Order (Generate QR)
Create payment order and receive QR string and UPI link. RefID must be unique for every 
transaction.
curl -X POST "https://yourdomain.com/api/api-payment/create-order" \
-H "x-api-key: your-api-key" \
-H "x-api-secret: your-api-secret" \
-H "Authorization: Bearer <token>" \
-H "Content-Type: application/json" \
-d '{
"RefID": "ORDER_12345",
"Amount": "1000", 
"Customer_Name": "John Doe", 
"Customer_Mobile": "9876543210",
"Customer_Email": "john@example.com"
}'
4. Check Payment Status
Check transaction status using txnId or refId. Poll every 3-5 seconds until status becomes 
SUCCESS, FAILED, or EXPIRED.
curl -X POST "https://yourdomain.com/api/api-payment/check-status" \
-H "x-api-key: your-api-key" \
-H "x-api-secret: your-api-secret" \
-H "Content-Type: application/json" \
-d '{
"txnId": "TXN_ABC123456"
}'
5. Complete Integration Flow
Step 1: Generate Token
Step 2: Create Order & Display QR
Step 3: User completes payment via UPI app 
Step 4: Poll check-status API
Step 5: On SUCCESS  Credit wallet / mark order paid
6. Common Error Codes
HTTP Code Meaning
400 Validation failed
401 Authentication failed
404 Transaction not found
409 Duplicate RefID
500 Server error
502 Provider erro

Payout API – Developer Integration Guide
Version 1.0 | UPI & IMPS Payout APIs
1. Introduction
This document explains how developers can integrate UPI and IMPS payout APIs. It coversrequest formats, responses, status 
handling, and best practices.
2. API Endpoints
Method Endpoint Description
POST /api/payout/upi Create UPI payout
POST /api/payout/imps Create IMPS payout
GET /api/payout/status Check payout status
3. Create UPI Payout
Content-Type: application/json
x-api-key: Your_api_key
x-api-secret: Your_secret_key

Endpoint: POST /api/payout/upi 
{
"p1": "123456852634", // UPI Id
"p3": "TXN875634257654”, // Client Transaction ID / Reference ID
"p4": "1", // Amount (ya amount multiplier / ₹1 test txn)
"p5": "Ramu" // Beneficiary Name
}

Endpoint: POST /api/payout/imps 
Content-Type: application/json
x-api-key: Your_api_key
x-api-secret: Your_secret_key

Required Fields:

"p1": "123456852634", // Account Number

5. Response Status Codes
1. Check Payout Status
Use the status API to check the latest payout status.
Example: GET /api/payout/status?clientTxnId=txn_10001

2. Best Practices
• Do not treat payout as successful until status is SUCCESS.
• Always use unique clientTxnId to avoid duplicate payouts.
• Show clear messages to users based on status.
